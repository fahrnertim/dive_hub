## Status and next steps

Review of the web client at `e3ab99c` (after slice 6), finished 2026-10-03. The project owner chose to
fix every finding; all four batches are done (see [Fix status](#fix-status)). The findings below are
kept as written at review time. Where the fix differs from the proposal, the notes below say how.

- **B5:** the page itself is the drop target in both layouts. React Aria's `DropZone` and its
  extra tab stop are gone, and "Import files" is the keyboard path.
- **C3, C4, C6:** the menus have text labels ("Recording actions", "More", the User's name); the
  icons slice adds glyphs.
- **C2:** a field changed and changed back within one merged entry drops out ("Changed and changed
  back" when nothing is left).
- **D:** `Intl.DurationFormat` is used where the browser has it (not in Node 22); font preloading was
  left out (Vite hashes the font file names, and `font-display: swap` already avoids invisible text).

Done afterwards (2026-10-03): **icons and motion** ([ADR 0018](../decisions/0018-icons-and-motion.md)). Originally planned as: Run the skills check for "icons"
first (AGENTS.md rule). Choosing an icon library is a decision for an ADR (candidates: Lucide,
Phosphor; MIT, tree-shakable). Motion follows the installed `emil-design-eng` skill and
`prefers-reduced-motion` (the tokens already zero the durations). Findings marked *(icons)* fit that slice.

## Method

- **Material**, captured with Playwright against the e2e server (`apps/web/e2e/review-material.capture.ts`):
  - screenshots of every page and state: light and dark, English and German, 1280 px and 390 px;
  - the accessibility tree of each page;
  - axe-core results (WCAG 2.2 AA plus best practices);
  - the Tab order of the main pages;
  - empty states (a freshly invited User) and error states (sign-in errors, unknown Dive).
- **Looked at:** all 16 screenshots, every `.aria.yml` tree, and `findings.json` (axe results and Tab order).
- **Code checked** against the pinned Vercel guidelines and the `accessibility` and `emil-design-eng`
  skills (interaction states). Every finding was confirmed in the code (file references below are
  under `apps/web/src/` unless stated otherwise).
- **Lenses:** Nielsen's ten usability heuristics, the sources below, and our [design system](../spec/design-system.md).

## Findings

Ranked by impact × effort. Effort: **S** up to an hour or two, **M** about half a day, **L** a slice of its own.

### Tier A — high impact, small effort (recommended fix slice)

| # | Finding | Proposed fix | Effort |
|---|---|---|---|
| A1 | **Bug: Devices show 0 recordings and no "last used".** In `apps/server/src/divers/diver-service.ts` `devices()`, the query reads from a single table, so Drizzle renders its columns unqualified. The subquery becomes `where "device_id" = "id"`, which compares against the recording's own id (seen with `toSQL()`). | Use a `left join recording … group by device.id` (or qualified raw SQL). Add the counts to the API test. | S |
| A2 | **Divers page scrolls the whole page sideways on phones** (390 px viewport, 472 px page), and each Device row is ~280 px tall. The cause: `.table-scroll` (`ui/ui.css:120`) isn't positioned, so the visually hidden label and React Aria's hidden select escape the scroll box. In addition, the 90-character hint "Imports from now on go to this Diver…" wraps one word per line in every row. WCAG 1.4.10. | `.table-scroll { position: relative }`. Say the hint once above the table. Give the "Belongs to" column a `min-width` (~10 rem). | S |
| A3 | **Unknown Dive shows "Loading…" for about a second** before the error appears: every non-401 error is retried once (`main.tsx:22`). The error state then has no heading and no way back (`DiveDetail.tsx:25`). | Don't retry 4xx responses. On the error state, show a heading "Dive not found" and a link back to the logbook. | S |
| A4 | **No level-one heading** on the logbook, dive, sign-in, setup, invitation and reset pages (axe `page-has-heading-one`). Divers, account and admin have one. | Give `Panel` a heading-level prop. The page title of each page ("Logbook", "Dive 42", "Sign in", …) becomes its `h1`. | S |
| A5 | **The page title is always "Dive Hub", and focus stays put on route changes** (`App.tsx`, `index.html`). Screen reader users get no cue that the page changed, and browser tabs and history all read the same. WCAG 2.4.2, 2.4.3. | Add a `usePageTitle()` hook per page ("Dive 42 – Dive Hub"). On route change, move focus to the `h1` (`tabIndex=-1`). | S |
| A6 | **Fields in the dive edit form lose information for screen readers.** The unit is `aria-hidden` and not part of the name (`ui/Fields.tsx:32`), so "Max depth" is read without "m". The "Recording: 18.5 m" hints are loose text, not linked to their fields (`DiveEditForm.tsx:122`). On the dive page, the recorded value behind "edited" is only in a `title` tooltip (`DiveDetail.tsx:96`), which keyboard and touch users can't reach. WCAG 1.3.1. | Put the unit into the accessible name as visually hidden text ("Max depth (m)"). Pass the hint through the field's `description` slot. Show the "edited" detail as visible text, or at least visually hidden text. | S |
| A7 | **"Make user" on the admin page.** It is offered on your own row and for the only admin, whom the server refuses to demote (`last_admin`). Self-demotion runs in one click with no confirmation, and `me` isn't refreshed afterwards (`Admin.tsx:154`). The label is unclear. | Hide the button for the last admin, or disable it with a reason. Confirm before demoting yourself, then refresh `me`. Rename it "Remove admin role" (de: "Adminrechte entziehen"). | S |
| A8 | **Buttons give no feedback while working.** `isDisabled={x.isPending}` drops keyboard focus to `<body>` and shows no busy cue. The upload button is never disabled, so files can be uploaded twice (`ImportPanel.tsx:39`). Sign-out has no `finally` and stays disabled forever after a failure (`Account.tsx:179`). | Use React Aria's `isPending` on `Button`: it keeps focus and announces. Add a pending style. Make the upload button pending while uploading. Put the sign-out in `try/finally`. | S |
| A9 | **Import outcome goes stale.** An Import still says "needs your decision" after the Recording was decided, because the outcome is stored once (`ImportPanel.tsx:62`). | Show the current state: once the candidate is resolved, the outcome reads "decided" and links to the resulting Dive. This can be derived from the open candidates, or the server can return it. | S–M |
| A10 | **Drop zone.** Its accessible name is doubled ("Drop Garmin FIT files or zips here" twice; `aria-label` plus `slot="label"`, `ImportPanel.tsx:32`). Dropping accepts any file type; only the picker filters to `.fit`/`.zip`. | Remove the `aria-label`. Filter dropped files by extension, and say which files were skipped. | S |
| A11 | **Phone header takes three rows**: brand + navigation, then name + sign out (`ui/ui.css:14`). The nav's `flex: 1` pushes the user menu to its own row. | At ≤ 40 rem: brand and user menu on row 1; the nav on row 2 (`order: 3; flex-basis: 100%`), scrolling sideways if needed. | S |
| A12 | **Identical control names repeat on every row**: "Revoke", "Rename", "Sign out", "Add to this dive", and three selects all named "Belongs to". A screen reader's list of controls can't tell them apart. Two table headers are empty (axe `empty-table-header`: account sessions, admin invitations). WCAG 2.4.6, 1.3.1. | Add an `aria-label` naming the row ("Revoke invitation for new@example.com", "Garmin Descent Mk3 111 belongs to"). Give the empty headers a visually hidden "Actions". | S |
| A13 | **Dialogs can't scroll on a phone.** `.modal-overlay` has no `overflow-y` (`ui/ui.css:132`), so a tall dialog is cut off. | `overflow-y: auto; overscroll-behavior: contain` on the overlay, and `overscroll-behavior: contain` on `.popover`. | S |

### Tier B — high impact, medium effort

| # | Finding | Proposed fix | Effort |
|---|---|---|---|
| B1 | **Focus falls to `<body>` after a view changes.** This happens when Edit dive opens or closes, when a candidate is resolved (the panel unmounts, `Decisions.tsx:21`), when a Diver is deleted or a rename ends, when an invitation is revoked, and after a User is deleted (the dialog returns focus to a row that no longer exists). WCAG 2.4.3. | Opening the edit form focuses its first field; closing it focuses "Edit dive". After a removal, focus the next item, or the panel heading (`tabIndex=-1`). | M |
| B2 | **Actions that are hard to undo run without asking**: split off (`DiveDetail.tsx:182`), revoke invitation, disable User, sign out everywhere, sign out other sessions, sign out the current session's row. Discard can be reopened, but nothing says so. Nielsen #3/#5. Delete User already asks (you type the e-mail). | Use the existing `Dialog` to confirm split off, disable, sign out everywhere and self-demotion. For revoke and discard, show a notice with "Undo" (reopen). | M |
| B3 | **Unsaved edits are lost silently.** Cancel, "Reload", the back link, the nav and closing the tab all drop the draft of the dive edit form (notes can be up to 20,000 characters). | When the form has changes: a `beforeunload` handler, a confirmation on hash change and on Cancel. | S–M |
| B4 | **Results of actions are not announced.** `Notice` mounts its `role=status` together with its text, which screen readers often don't read (e.g. "Password changed"). These say nothing at all: uploading, Import status changes, saving a Dive, adding a Diver, saving preferences, Copy → Copied. WCAG 4.1.3. | One polite live region that is always in the DOM, with an `announce()` helper. Errors keep `role=alert`. | M |
| B5 | **Import dominates the logbook.** For a returning User, the Import panel and its history (up to 8 rows) sit above the dives. | When the User already has Dives: the logbook comes first, Import becomes a compact "Import files" button, and files can be dropped anywhere on the page. The history shows running and recent Imports, the rest behind "Show all". Keep today's layout for the empty logbook (first run). | M |
| B6 | **The depth profile has no text alternative and no keyboard access.** The `role=img` is named only "Depth profile". Its legend reads "Time: – Depth: – Temperature: –" until the pointer is on the chart, which looks broken (`DepthProfile.tsx:100`). WCAG 1.1.1, 2.1.1. | Hide the legend values until hovering, or show the dive's summary there. Describe the chart via `aria-describedby` (max depth at minute N, duration, temperature range). Optionally add the samples as a table inside `<details>`. | M |

### Tier C — structure and content, own slices or later

| # | Finding | Proposed fix | Effort |
|---|---|---|---|
| C1 | **No paging, sorting or search in the logbook.** The API silently returns the latest 500 Dives (`apps/server/src/routes.ts:139`). This is needed before real logbooks (hundreds of Dives) arrive. | Cursor paging in the API (by start time); sorting by date, depth and duration; search by number, site and notes later. The API's paging shape is worth an ADR. | L |
| C2 | **Dive history grows long**: every edit is an entry. | Show the latest 3 entries, the rest behind "Show all". Merge consecutive edits by the same person within a few minutes. | M |
| C3 | **The Recordings panel is verbose.** "Split off into its own dive" plus its explanation is always visible. The selector is a radio group that switches the view, which makes it really tabs. The selected Recording is not in the URL. | Tabs for the Recordings. Secondary actions (split off, make primary) in a menu *(icons)*. `#/dives/<id>?recording=<rid>`. | M |
| C4 | **Dive page on a phone**: "Edit dive" and "Move to another Diver…" sit between the date and "Diver: Erika". | Put Diver right under the date. Move "Move to another Diver…" into the same secondary-actions menu as C3 *(icons)*. | S |
| C5 | **Admin tables on a phone** cut off the actions column; it scrolls sideways with no visible hint. | Card-style rows below 40 rem (one card per User or Invitation, actions at the bottom). | M |
| C6 | **The User's name is the only link to "My account"**, and it doesn't look like an account link. | A labelled account item (icon + name, or a menu with "My account" and "Sign out") *(icons)*. | S |
| C7 | **The empty logbook** says only "No dives yet. Import a FIT file above." | A first-run hint on how to get files out of Garmin Connect ("Export Original") or off the watch over USB, linking to Import. | S |
| C8 | **The sign-in and invitation pages** say nothing about what Dive Hub is. | One line under the brand ("Your club's shared dive logbook" or similar). | S |
| C9 | **Two Divers can have the same name** ("Mia" twice) without any warning, and then can't be told apart in the logbook filter. | Warn on add/rename when the name already exists (still allowed). | S |
| C10 | **Loading states are text only.** "Loading…" with no reserved space makes the page jump when content arrives. The Divers list has no loading state at all (`DiversPage.tsx:40`). | Placeholders of a fixed size for the dive facts and the chart (320 px); a loading state for the Divers list. | M |

### Tier D — polish (bundle with the icons-and-motion slice, or whenever a file is touched)

**Interaction states** (`ui/ui.css`, `pages.css`; emil-design-eng):

| Before | After | Why |
| --- | --- | --- |
| No hover on inputs, select button, checkbox/radio, recording segments, drop zone | Border goes to `--color-text-muted` on `[data-hovered]` | Every control shows it reacts to the pointer |
| Hover rules apply on touch too | Wrap hover rules in `@media (hover: hover)` | Sticky hover after a tap on phones |
| `.btn[data-pressed] { transform: translateY(1px) }`, no transform transition | `transform: scale(0.97)` with `transition: transform var(--duration-fast) ease-out` | Press feels responsive; durations already drop to 0 for reduced motion |
| Disabled inputs and checkboxes look enabled | `[data-disabled]` styles (reduced opacity, `cursor: not-allowed`) as on `.btn` | States must be visible |
| Select has no open state | `[data-pressed]`/`[aria-expanded=true]` style on the select button | Shows which control the popover belongs to |
| `.btn-quiet` ~25 px tall, 0 horizontal padding, 4 px gaps | `min-height: 2rem`, inline padding with a negative margin | Comfortable targets (WCAG 2.5.8 passes only narrowly) |

**Small things:**
- No `<meta name="theme-color">` for light and dark.
- No `touch-action: manipulation` or `-webkit-tap-highlight-color` on buttons and links.
- No `text-wrap: balance` on headings.
- `overflow-wrap: anywhere` is missing on `.notes`, so a long URL breaks the panel (`pages.css:37`).
- No `translate="no"` on "Dive Hub", device names and serial numbers.
- German "Wird geladen …" should use a non-breaking space before "…".
- The history line `field: a → b` is glued together from pieces (`DiveHistory.tsx:50`), against our `<Trans>` rule.
- `formatDuration` builds "1 h 5 min" by hand; `Intl.DurationFormat` does it.
- The device-name fallback "Browser" is not translated (`AccountPage.tsx:110`).
- The logbook `<tr onClick>` ignores Ctrl/Cmd/middle-click (`DiveList.tsx:46`).
- "Save" is vague: use "Save dive" / "Save name".
- Chart: the temperature line is faint on the dark gradient (1 px, dash 4/4; use 1.5 px, dash 6/4). Chart colours don't follow an OS theme switch until reload.
- Long notes need no further fix beyond `overflow-wrap`; the logbook needs no virtualization once C1 pages it.

### Checked and fine

- Contrast: no axe contrast violations in light or dark mode.
- Visible `:focus-visible` everywhere. The Tab order is logical: skip link, brand, navigation, user menu, content.
- Labels on every field. Native validation focuses the first error; errors are `role=alert`.
- Correct `type` and `autocomplete` on sign-in, setup, invitation, reset and password fields.
- Real `<a>` links. The logbook Diver filter is in the URL. `aria-current` on the navigation.
- Tables have labels, column headers and a focusable scroll region.
- Dates, numbers, units and chart axes go through `Intl` ("25,8" in German). Tabular figures. Curly quotes and "…" in both languages.
- No `transition: all`. Durations drop to 0 under `prefers-reduced-motion`.
- `BrandMark` is `aria-hidden` and has a size. `color-scheme` is set.
- The delete-User dialog asks for the e-mail. React Aria's Dialog keeps focus inside.
